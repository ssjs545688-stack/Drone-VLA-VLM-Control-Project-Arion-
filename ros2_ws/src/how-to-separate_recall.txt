reverce_plan과 goto_history의 분리
`goto_history`와 `reverse_plan`은 단지 목적지만 다른 것이 아니라, **복귀하는 방식(비행 알고리즘)**이 완전히 다르기 때문입니다.

### 1. 두 함수가 구분되는 방식

* **`goto_history` (직선 복귀)**
  * 중간 비행 경로를 다 무시하고, 기록된 특정 좌표로 **직선 비행하여 돌아가는 방식**입니다.
  * 어느 위치로 직선 복귀할지 구별해야 하므로 **`recall` 파라미터**를 사용합니다.
    * `recall="previous"`: **직전 명령 시작 위치**로 직선 복귀
    * `recall="first"`: **최초 출발지(원점)**로 직선 복귀

* **`reverse_plan` (경로 역순 되짚기 / 백트래킹)**
  * 직선으로 바로 날아가는 것이 아니라, 지금까지 실제로 수행했던 이동 스텝(예: A-> B -> C)을 **역순C -> B -> A)으로 하나씩 거꾸로 수행하며 출발지로 되돌아가는 방식**입니다.
  * 수행해 온 전체 플랜을 거꾸로 밟아가는 동작이므로 별도의 인자 없이 **`arguments={}` (빈 값)으로 호출**합니다.
### 2. 자연어 명령 예시로 보는 차이

 자연어 명령 / 호출되는 Tool Call / 비행 동작 방식
-"방금 전 위치로 돌아가"/ `<tool_call>{"name": "goto_history", "arguments": {"recall": "previous"}}</tool_call>` / 직전 위치로 직선 복귀

-"처음 출발했던 곳으로 바로 돌아가"/ '<tool_call>{"name": "goto_history", "arguments": {"recall": "first"}}</tool_call>` / 출발지로 장애물 무시하고 직선 복귀

-"지금까지 온 길을 거꾸로 되짚어가" / `<tool_call>{"name": "reverse_plan", "arguments": {}}</tool_call>` / 지금까지 이동한 스텝을 역순으로 거꾸로 비행

### 💡 결론

* `goto_history`는 **직선 이동 복귀**이므로 `previous`(직전)와 `first`(처음) 두 가지 인자를 모두 가질 수 있습니다.
* `reverse_plan`은 **경로 백트래킹 복귀**이므로 인자가 필요 없는 독립된 함수입니다.

###first와 call의 혼동?

 현재 스키마 및 엔진 설계(schema.py, qwen_engine.py)에서는 이러한 혼동을 방지하기 위해 다음과 같은 장치들을 두고 있습니다:

1. 시스템 프롬프트 명시적 규칙 및 예시 구체화
 시스템 프롬프트(SYSTEM_PROMPT) 규칙에 goto_history(previous)는 "직전 명령 시작 위치", goto_history(first)는 **"최초 기록된 출발 위치"**로 명확히 정의하고 있습니다
 또한 예시(Few-shot)에 "방금 전 위치로 돌아가" ➔ previous, "처음 출발했던 곳으로 돌아가" ➔ first 구분을 명시하여 모델이 어휘 패턴을 학습하도록 합니다.

2. 파라미터 레벨 description 구체화
 함수 상단 설명뿐만 아니라 recall 파라미터 내부 description에 "previous는 직전 명령 시작 위치, first는 최초 기록된 출발지/원점입니다."라고 각각의 대상을 명확히 서술해 두었습니다.
 
3. 파인튜닝 데이터셋 사전 학습
 파인튜닝 데이터 생성 시 "방금 전", "직전", "한 단계 전"은 previous로, "처음", "원점", "출발지", "시작 지점"은 first로 매핑된 다량의 구어체 데이터를 학습시켜 유의어 구분 능력을 강화합니다.
 
### how to 튜닝

1. 어휘 및 키워드 대립쌍 데이터 구성학습 데이터셋 생성 시 두 인자에 대응하는 자연어 키워드 군을 명확히 분리하여 1:1에 가깝게 균형 있게 배정해야 합니다.
-recall="previous" (직전 명령 시작 위치)2:핵심 키워드: "방금 전", "직전", "바로 전", "한 단계 전", "이전 지점", "조금 전"
--학습 문장 예시:"방금 전 위치로 돌아가"3"직전 위치로 복귀해줘""바로 전에 있던 곳으로 다시 가""한 단계 전 위치 복귀" (조사 생략 패턴)

-recall="first" (최초 출발지/원점)2:핵심 키워드: "처음", "원점", "출발지", "시작 위치", "최초 이륙 장소", "홈(Home)"
--학습 문장 예시:"처음 출발했던 곳으로 돌아가"4"원점으로 바로 복귀해라""시작했던 출발 지점으로 가""최초 이륙 장소 복귀" (조사 생략 패턴)
2. 하드 네거티브 대립 쌍 학습
 비슷한 문장 구조에서 단어 하나(직전 vs 처음) 차이로 Target Tool Call이 갈리는 하드 샘플을 대량으로 포함시켜 모델이 결정적 키워드에 민감하게 반응하도록 훈련시킵니다.
 -대립 예시 1
 :"직전 위치로 가" -> <tool_call>{"name": "goto_history", "arguments": {"recall": "previous"}}</tool_call>
 :"최초 위치로 가" -> <tool_call>{"name": "goto_history", "arguments": {"recall": "first"}}</tool_call>

 -대립 예시 2
 :"방금 이동했던 곳으로 돌아가" -> previous"
  처음 이륙했던 곳으로 돌아가" -> first
3. reverse_plan과의 3자 경계 명확화
 복귀 관련 명령은 goto_history(previous)와 goto_history(first) 외에도 **reverse_plan(경로 역순 되짚기)**이 존재합니다.따라서 모델이 직선 복귀(goto_history)와 백트래킹(reverse_plan)까지 혼동하지 않도록 3자 간의 구분을 파인튜닝 데이터에 포함해야 합니다.
 
Target--Tool--Call
직전 위치 직선 복귀 --"방금 전 위치로 가"--goto_history(recall="previous")
원점/출발지 직선 복귀--"처음 출발지로 바로 가"--goto_history(recall="first")
경로 역순 백트래킹--"왔던 길을 거꾸로 되짚어가"--reverse_plan(). 

System Prompt 및 Schema Description과의 완전 동기화
학습 데이터셋을 구성할 때 schema.py에 정의된 **SYSTEM_PROMPT 규칙(Rule 8, 9, 10)**과 **recall 파라미터의 description**이 학습 시 전달되는 프롬프트와 100% 동일한 포맷을 유지해야 합니다.
qwen_engine.py에서 tokenizer.apply_chat_template을 호출할 때 들어가는 시스템 프롬프트25가 학습 데이터셋의 {"role": "system", "content": ...}와 정확히 일치해야, 0.6B 모델이 파인튜닝 후에도 시스템 프롬프트의 지침을 완벽하게 이행하게 됩니다.


reverce_plan과 goto_history의 분리

2. 학습 데이터셋 충돌 방지 및 해결 방법
"출발지로 돌아가"라는 단순 명령만 넣으면 두 함수 간에 모호성이 발생하므로, 파인튜닝 데이터셋 생성 시 아래와 같이 키워드 조건을 명확히 분리해야 모델이 오판하지 않습니다.
1) goto_history(recall="first") 키워드 다듬기 (직선/바로 강조)
단순히 "출발지로 가" 대신 "바로", "직선으로", "직행", "점프하여" 같은 단어를 필수 조합으로 구성합니다
.
수정된 학습 예시:
"처음 출발했던 곳으로 바로 돌아가"
"원점으로 직선 복귀해라"
"시작했던 출발 지점으로 직행해"
"최초 이륙 장소로 바로 복귀" (조사 생략 패턴)
2) reverse_plan() 키워드 다듬기 (경로/거꾸로/역순 강조)
단순 목적지가 아닌 "왔던 길", "거꾸로", "역순", "경로 따라", "되짚어" 등 과정 표현이 들어갈 때만 호출되도록 구성합니다
.
학습 예시:
"왔던 길 그대로 되돌아가줘"
"이동했던 경로 역순으로 되짚어가며 복귀해"
"방금 비행했던 길 거꾸로 가줘"
"왔던 비행 경로 그대로 백트래킹해라"
